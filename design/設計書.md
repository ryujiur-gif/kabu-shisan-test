# 株予想 試験運用プログラム 設計書（2026-11-08）

## 1. 目的と背景
- 世界情勢・イベントを毎朝確認し、日本株の「買い時の銘柄」「売り時の銘柄」（各0〜2銘柄）と持ち株の見通しをスマホに通知する。
- 当面は**試験運用**。仮想の100万円でおすすめ通りに売買していたら収支がどうなるかを記録し、予想が役に立つかを見極める。
- 成功の姿：毎朝スマホで通知を受け取り、いつでも成績（総資産・損益・日経平均との比較）を確認できること。

## 2. やること / やらないこと
- やる：ニュース調査、銘柄選定、メール通知、仮想売買の記録、成績ページ。
- やらない：実際の証券口座での売買。手数料・税金の計算（当面は無視、後で追加可能）。空売り。
- 失敗とみなす状態：通知が届かない日が続く／記録が実際の株価とずれる／日経平均との比較ができず良し悪しが判断できない。

## 4. 仕組み（Claudeの判断で決めた部分は【案】）
### 4.1 全体構成【案】
- **Claudeのクラウド定期実行（ルーティン）**が毎朝7時（日本時間）に起動。PC不要。
- 記録とプログラムは **GitHub の非公開リポジトリ**（名前案：`kabu-shisan-test`）に保存。
- 決まった計算（株価取得・売買の確定・成績集計・成績ページ作成）は Python プログラムで行い、計算ミスが出ないようにする。
- ニュース調査と銘柄選びは Claude が行い、結果を決まった形式（JSON）でリポジトリに書く。
- メール送信は Gmail コネクタを使う。

### 4.2 毎朝の流れ【案】
1. 休場日（土日・祝日・12/31〜1/3）なら何もせず終了。
2. **前営業日の注文を確定**：前日朝に通知した売買を、前営業日の**始値**で成立させる（売りを先、買いは売却代金も使ってよい）。
3. 前営業日の終値で持ち株を評価し、総資産・損益・日経平均比を記録。
4. ニュースを調べる：前夜の米国市場、為替、金利、地政学、主要企業の決算・材料など。
5. **日経225採用銘柄**から、基準を満たす買い銘柄を0〜2銘柄選ぶ（持ち株と重複可）。各銘柄に理由（根拠のニュース）と期待度（高・中・低）を付ける。
6. 買い・売りとも毎日0〜2銘柄で、基準を満たすときだけ行う（買い0・売り0の日もある）。持ち株はすべて毎日「上昇（まだ上がりそう）／横ばい／下落（まだ下がりそう）」の見通しを出す。売りは損切り（−8%以下）・買った理由が崩れた・下落予想・利益確定（+15%以上かつ過熱かつ上昇予想でない）のとき。購入から5営業日以内は損切り・悪材料以外では売らない。買いは材料・値動き・財務・相場環境の4条件をすべて満たすときだけ。詳細は ROUTINE.md 手順4。（2026-11-10 変更：以前は毎日2銘柄を必ず買い・必ず売っていた）
7. 注文として記録し、メールを送り、成績ページを更新して GitHub に保存。
8. （2026-11-10 追加）経済イベントの日程表 `data/events.csv`（FOMC・日銀会合・SQ・休場日など）をプログラムが資料に載せ、重要イベントの前日・当日は買いを控える。日程表は担当が週1回検索で確認・更新する。資料には「日経先物と前日の日経平均終値の差」も載せる。自動実行が遅れて取引時間中に動いても、当日の途中の値は資料に使わない。株価が一部でも取れない日は確定を翌日に持ち越す。朝の担当のモデルは Opus 5.5。

### 4.3 売買ルール【案】
- 購入金額：期待度 高=総資産の20%、中=10%、低=5%（総資産＝現金＋持ち株の時価。2026-11-10 変更：以前は固定の20万/10万/5万円）。買った後も現金を総資産の10%以上残し、1銘柄は総資産の30%まで。現金比率の目安（リスクオン20〜40%・中立30〜50%・リスクオフ50〜80%）を売買判断に使う。1株単位（単元未満株）で、`株数 = 金額 ÷ 始値（切り捨て）`。現金不足なら買える分だけ。
- 売却：選ばれた銘柄は**全株**売却。
- 約定価格：通知当日の始値。株価は Yahoo Finance（無料）から取得、取れない場合は別の無料データ（stooq）に切り替え。
- 当日の始値が取れない銘柄（売買停止など）は注文取消として記録。

### 4.4 メールの内容【案】
- 件名例：`【株予想】11/9 買い：トヨタ・ソニー／売り：○○・△△`
- 本文：本日の買い・売り銘柄と理由・期待度、昨日の約定結果、総資産と損益（円・％）、日経平均との比較、成績ページへのリンク。
- 最後に「試験運用・投資判断は自己責任」の注記。

### 4.5 成績ページ【案】
- スマホで見やすい1ページ：総資産の推移グラフ（日経平均に同額投資した場合と並べる）、持ち株一覧（取得単価・現在値・損益）、取引履歴、日々の予想の的中状況。

## 5. 制約・注意点
- 予想の的中は保証できない。成績ページは日経平均との比較で冷静に評価できる形にする。
- クラウド実行は Claude の契約の利用枠を使う（毎朝1回程度）。
- 無料の株価データはクラウドから取得を断られる可能性がある → 作成時に実際に試して確認する。
- 日経225の銘柄一覧は定期的な入れ替えがあるため、ファイルで管理し必要時に更新する。

## 8. 振り返りと学習・毎朝の点検（2026-11-12 追加）
### 8.1 予想の振り返り（プログラムが毎朝集計）
- 買い予想ごとに、買った日の始値から 1・3・5・10・20営業日後の騰落率と、同じ期間の日経平均との差を記録する。**主な物差しは5営業日後**（その前に売ったら売値）。「成功」＝上昇し日経平均にも勝った、「失敗」＝下落し日経平均にも負けた。
- 売りは、売った後5営業日の値動きで「売って正解」か「早売り」かを判定する。
- 持ち株の見通し（上昇／横ばい／下落）は5営業日後の実際と照らして的中率を出す。
- 資産全体の日経平均との差を「現金で持っていた分」と「銘柄選びの分」に分ける（概算）。
- 条件別の成績（期待度・ビジネスモデルの型・相場環境・前日の値動き・寄り付きの位置・RSI・25日線乖離・出来高・材料の種類・業種）を集計し、**同じ条件が5件以上で、他の事例より成績がはっきり悪い（良い）ものを「傾向」**、5件未満を「仮説」として対策の文と一緒に出す。
- 結果は `data/review/lessons.md`・`review.json` に保存し、朝の資料の先頭・メール・成績ページに載せる。

### 8.2 学習（朝の担当が書く）
- `data/review/journal.md`：結果が出た事例を1件ずつ振り返る（予想・結果・原因・教訓）。未記入だと仕上げがエラーにする（1日最大3件）。
- `data/review/playbook.md`：振り返りから作るルール集（最大12個。仮説／傾向／廃止を区別）。毎朝の資料に写しが載る。手順書の基準そのものの変更は「竜司さんへの提案」に書き、勝手には変えない。
- 注文ファイルの `learned`：その日の判断に振り返りをどう反映したか。メールに載る。
- 今日の買いが過去の「弱み」の条件に当てはまると、メールに「過去の傾向からの注意」が自動で付く。

### 8.3 毎朝の点検と自動修復
- 点検：口座の記録と取引履歴のつじつま、確定されていない注文、前営業日の予想の作り忘れ、成績の記録の抜け、日経平均が前営業日の値か、日程表・財務データの古さ。問題は朝の資料の先頭とメールの注記に出る。
- 修復：成績の記録に抜けた営業日は取引履歴と株価から自動で埋める。日経平均が古いときは記録済みの終値で差し替える。株価の取得は3つの経路＋再試行。
- 同じ日に準備が何度動いても安全：確定済みの日を「失敗」で上書きしない。朝の資料は取引開始（8:50）以降は作り直さない。
- 手順書で「買わない」と決めている条件（RSI 75以上・25日線乖離+15%以上・重要イベントの日の期待度 高/中）は仕上げがエラーにする。
